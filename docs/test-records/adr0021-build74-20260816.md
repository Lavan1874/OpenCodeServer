## Designated Requirement migration evidence

Build 73 was the installed outgoing candidate:

```text
Build 73 authority = OpenCodeServer Local Signing
Build 73 CDHash = 85637dae800bc1fc0807227bdebefcfaf57f7528
Build 73 DR = identifier "ai.opencode.server" and certificate root = H"<self-signed-sha1>"
```

Build 74 has the Apple-issued, team-anchored requirement:

```text
Build 74 authority = Apple Development: <developer-account> (<leaf-id>)
Build 74 DR = identifier "ai.opencode.server" and anchor apple generic and certificate leaf[subject.CN] = "Apple Development: <developer-account> (<leaf-id>)" and certificate 1[field.1.2.840.113635.100.6.2.1] /* exists */
```

The two directed tests used `codesign --verify -R` and both rejected the
opposite requirement:

```text
Build 74 tested against Build 73 DR: test-requirement failed
Build 73 tested against Build 74 DR: test-requirement failed
```

This is the expected one-way migration evidence; no requirement was weakened
to a bundle-identifier-only rule.

The revised installer gate was exercised against the actual installed Build
73 and candidate Build 74:

```text
identity-change previous leaf authority: OpenCodeServer Local Signing
identity-change candidate leaf authority: Apple Development: <developer-account> (<leaf-id>)
identity-change previous designated requirement: identifier "ai.opencode.server" and certificate root = H"<self-signed-sha1>"
identity-change candidate designated requirement: identifier "ai.opencode.server" and anchor apple generic and certificate leaf[subject.CN] = "Apple Development: <developer-account> (<leaf-id>)" and certificate 1[field.1.2.840.113635.100.6.2.1] /* exists */
Designated Requirements are recorded as a one-way identity transition
```

Wrong declared outgoing or incoming authorities were each rejected
fail-closed. The unchanged default mode accepted same-identity temporary
copies, and the complete existing `scripts/test_install.sh` fault-injection
suite passed.

## Phase 2 result

Build 74 is a passing Release candidate for the Phase 3 migration install.
No certificate was exported, no private key or `.p12` was created, and no
Phase 5 expiry experiment or Phase 6 re-sign was performed.
